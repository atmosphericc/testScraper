# Walmart Checkout Fixes - 2026-04-29

## Issue: Infinite Modal Loop During Checkout

**Symptom**: During Walmart checkout, the "What day works best for you?" delivery modal would get stuck in an infinite click loop. The logs showed "Selected delivery day" being repeated 10+ times before the checkout would hang. Akamai/PerimeterX would eventually block the session with a `/blocked` challenge.

**Additional Issue**: After each purchase attempt, the stock monitor would accumulate 200-1200+ errors within 3-4 minutes, dropping to 0% success rate.

## Root Causes

### Modal Infinite Loop
1. `_handle_delivery_day_modal()` would find and click buttons in the modal
2. **Never verified** if the modal actually closed after clicking
3. **No limit** on how many times modal handling would be called per checkout
4. Generic selector `[role="dialog"] button:not([aria-label*="close"])` could match any button

### Stock Monitor Blocking
1. After purchase flow (Tab 2), session cookies became stale
2. Stock monitor (Tab 1) still used old cookies cached before purchase
3. Behavioral pattern mismatch → Akamai flagged as suspicious
4. No session refresh between purchases

## Fixes Applied

### Fix 1: Modal Visibility Verification
**File**: `walmart/purchase_executor.py:_handle_delivery_day_modal()`

Added explicit JS check for modal visibility before interaction:
```javascript
modal_visible = await self._page.evaluate("""
    () => !!(document.querySelector('[role="dialog"]') &&
             document.querySelector('[role="dialog"]').offsetParent !== null)
""")
```

**Benefit**: Only attempt to interact if modal truly exists and is visible.

### Fix 2: Modal Closure Verification
After clicking a button, verify the modal actually closed:
```javascript
modal_still_visible = await self._page.evaluate("""
    () => !!(document.querySelector('[role="dialog"]') &&
             document.querySelector('[role="dialog"]').offsetParent !== null)
""")

if not modal_still_visible:
    return True  # Success — modal closed
else:
    return False  # Failed — button didn't close modal
```

**Benefit**: Prevents retrying if clicked button wasn't valid.

### Fix 3: Modal Handling Loop Prevention
**File**: `walmart/purchase_executor.py:_confirm_shipping()`

Added counter to limit modal handling attempts:
```python
modal_handle_count = 0
MAX_MODAL_HANDLES = 3

if modal_handle_count < MAX_MODAL_HANDLES:
    modal_dismissed = await self._handle_delivery_day_modal(f"{step_num}")
    if modal_dismissed:
        modal_handle_count += 1
```

**Benefit**: Even if modal keeps appearing, checkout continues after 3 attempts.

### Fix 4: Session Re-warm After Purchase
**File**: `walmart/purchase_executor.py:_clear_cart()`

Added call to refresh Tab 1's cookies after each purchase:
```python
if self._session and hasattr(self._session, 'rewarm_tab1'):
    try:
        logger.info("[PURCHASE] Re-warming Tab 1 after purchase...")
        await self._session.rewarm_tab1()
    except Exception as e:
        logger.warning("[PURCHASE] Tab 1 rewarm failed: %s (stock monitor may be briefly blocked)", e)
```

**Benefit**: Stock monitor gets fresh cookies and behavioral profile alignment after each purchase.

### Fix 5: Improved Logging
Changed DEBUG level logs to INFO level for visibility:
- Modal visibility check: INFO
- Modal closure verification: INFO
- Modal handling attempts: INFO with counters (e.g., "1/3")
- Screenshots saved on modal detection failures

**Benefit**: Can diagnose flyout/modal issues in production logs.
