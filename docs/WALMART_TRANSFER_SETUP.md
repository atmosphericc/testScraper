# Walmart Bot — New Machine Setup (after `git pull`)

You pulled this repo onto a different computer to run the Walmart capture
dry-run. This is the "what do I do now" guide. It covers what the new files do
and the exact sequence to go from a fresh clone to a working drop run.

> The minute-by-minute for the actual drop is `docs/DROP_DAY_PLAYBOOK.md`.
> The overall plan/expectations are in `docs/POKEMON_DROP_READINESS.md`.

---

## What does NOT transfer over git (you must recreate these on the new box)

These are gitignored on purpose — secrets and machine-specific state. A fresh
clone will NOT have them, and that's correct:

| Not transferred | Why | How to recreate on the new box |
|---|---|---|
| `.env` (your creds) | secrets | `cp .env.example .env`, then fill in real values |
| `walmart-profile-login/` | your logged-in Chrome profile | `python walmart_relogin.py` (log in by hand) |
| `state/walmart_session_profiles/` | seeded sessions | `python -m walmart.walmart_session_bootstrap` |
| `walmart-profile/cookies.json` | live cookies | regenerated by relogin |
| `logs/`, capture `.jsonl` | run output | created when the bot runs |
| `venv/` | the Python env | recreate (see step 1) — venvs are not portable |

Everything else — all the code, configs, and docs — comes over with the pull.

## Setup sequence (do this once on the new machine)

### 1. Python env + dependencies

Needs **Python 3.12** (this repo was built on 3.12.3). A venv from the old
machine will NOT work copied over — create a fresh one:

```bash
cd <repo>
python3 -m venv venv
./venv/bin/python -m pip install -r requirements.txt
```

`requirements.txt` = flask, requests, zendriver, waitress, patchright.
(zendriver drives Chrome — the new box needs Google Chrome installed.)

Windows: use `python -m venv venv` then `venv\Scripts\python -m pip install -r requirements.txt`.

### 2. Credentials

```bash
cp .env.example .env
```

Edit `.env` and fill in `WALMART_EMAIL`, `WALMART_PASSWORD`, `WALMART_CVV`.
Ideally the account is SMS-verified and has Walmart+ (see the playbook for why).

### 3. Log in + seed sessions

```bash
python walmart_relogin.py                       # log in by hand, press Enter
python -m walmart.walmart_session_bootstrap      # seed sessions, answer y
```

### 4. Proxies

`config/proxyIps.json` transfers with the repo (it's tracked). Heads-up: the
IPs in it are labelled for Target (`zone-main_proxy_target_50`). They may work
for Walmart, but if the drop shows lots of `456 Access Denied`, swap in fresh
residential/ISP proxies in the `proxies` list.

### 5. Confirm readiness

```bash
python walmart_preflight.py
```

Fix every 🔴 STOP it reports. Re-run until it's green (or only 🟡 WARNs you
understand). Exit code is 0 when there are no blockers.

## The tools you now have (what each file does)

**Operator scripts (run these):**

- **`walmart_preflight.py`** — "Am I ready?" Plain-language GO/WARN/STOP for
  every prerequisite (creds, login freshness, seeded sessions, proxies, armed
  SKUs) + warnings about SMS/Walmart+ you can't detect from disk. Read-only.
  Run at T-90 and T-60. Exits 1 on any blocker so a launcher can gate on it.

- **`run_walmart_capture_dryrun.sh`** — the Wednesday launcher. Runs preflight,
  then starts the full flow with `FINAL_PURCHASE=NO` so it **captures the real
  drop but never buys** (monitor → queue → admit → ATC → build checkout →
  stop + clear cart). Windows: set the 5 env vars listed in the script header,
  then `python -m walmart.walmart_app`.

- **`analyze_queue_capture.py`** — run AFTER the drop. Reads the capture files
  and prints: the drop timeline, the real queue ticket shape vs. what the code
  assumes, live-vs-hardcoded GraphQL checkout hashes (the payoff — stale ones
  are why real checkout fails), and any 456/PerimeterX blocks.

- **`run_walmart_bot_with_nightly_restart.bat`** — Windows overnight wrapper
  (crash + zombie restart) for a real (buying) run later. Not needed for the
  capture dry-run. Uses `walmart_health_probe.py` to detect a dead monitor.

- **`walmart_health_probe.py`** — helper the .bat uses; checks the app's log to
  tell "monitor running" from "dashboard-only zombie". Not run directly.

**New library module:**

- **`walmart/queue_events.py`** — the capture engine. Two env-gated JSONL sinks
  (event timeline, default on; raw body capture, opt-in). Wired into
  `queue_handler.py`, `queue_race.py`, `checkout_api.py`, `purchase_executor.py`.
  Output goes to `logs/queue_events_*.jsonl` and `logs/queue_capture_*.jsonl`.

## Then: run the drop

Follow `docs/DROP_DAY_PLAYBOOK.md`. In short: arm this Wednesday's real SKU in
`walmart/walmart_config.json` (get the item_id from the product URL), run
`walmart_preflight.py` until green, launch `./run_walmart_capture_dryrun.sh` at
~T-60, watch the logs, and run `analyze_queue_capture.py` afterward.

**Goal of this first run: capture data, not win.** The logs are the gold.
